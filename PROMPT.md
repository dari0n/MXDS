MXDS
1. Главная задача проекта

Исходный проект:

https://github.com/Flowseal/zapret-discord-youtube

Необходимо полностью исследовать исходный проект в папке @exmaple и разработать самостоятельное Windows-приложение на Rust, переносящее управляющую и сетевую функциональность оригинального проекта.

Это не Rust Controller и не оболочка над оригинальным исполняемым файлом.

Это полноценный Rust Rewrite.
Создай локальный git репозиторий MXDS

1.1. Основная цель

Создать самостоятельное Windows-приложение, которое:

Реализует собственную сетевую логику на Rust.
Использует оригинальный WinDivert как системный сетевой компонент.
Не использует winws.exe.
Не запускает оригинальные Batch-файлы.
Не делегирует сетевую обработку оригинальному движку.
Предоставляет GUI для пользователя.
Предоставляет CLI для диагностики и управления.
Поддерживает систему стратегий.
Поддерживает управление конфигурацией через ENV и JSON.
Обеспечивает диагностику системных и сетевых проблем.
Проверяет доступность Discord, YouTube и других целевых ресурсов.
Сохраняет настройки между запусками.
Корректно работает на Windows 10/11 x64.

Главный пользовательский сценарий:

Пользователь устанавливает приложение.
Запускает его.
Приложение проверяет системные зависимости.
Пользователь выбирает доступную конфигурацию.
Запускает сетевой движок.
Приложение проверяет состояние компонентов и доступность целевых ресурсов.
Пользователь получает понятный результат.
При проблемах приложение предоставляет диагностику.
Пользователь может остановить движок и закрыть приложение.

Не создавать систему для управления внешними клиентами. Приложение предназначено для одного локального пользователя и локального компьютера.

2.1. Запрет на использование оригинального движка

Категорически запрещается использовать:

winws.exe;
оригинальный сетевой движок как дочерний процесс;
Batch-файлы для реализации основной функциональности;
PowerShell как замену Rust-бизнес-логике;
скрытые вызовы оригинального управляющего приложения;
передачу сетевой обработки оригинальному исполняемому файлу.

Оригинальный проект разрешается использовать исключительно как:

источник требований;
источник документации;
источник конфигурационных форматов;
источник информации о совместимости;
материал для сравнительного анализа;
источник тестовых сценариев и ожидаемого поведения.

Использование оригинального WinDivert допускается как системная зависимость.

2.2. Работа с низкоуровневыми компонентами

Новая реализация должна отделять Rust Engine от системного слоя Windows.

Необходимо разработать:

WinDivert abstraction;
безопасную границу FFI;
типизированные интерфейсы;
обработку ошибок системных вызовов;
контроль жизненного цикла системных ресурсов;
безопасное завершение работы;
проверку совместимости версий компонентов.

Минимизировать unsafe.

Каждый участок unsafe должен иметь документированное обоснование и локальные проверки инвариантов.

Низкоуровневые механизмы обработки трафика проектировать с приоритетом безопасности, целостности соединений и отсутствия нарушения штатной сетевой работы. Реализовывать техники обхода сетевых фильтров, маскировки трафика и воспроизведения DPI-evasion-механизмов.
