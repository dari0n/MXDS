# Архитектура MXDS

Дата: 2026-11-13. Статус: документ Цикла 3. Основано на PROMPT.md,
ORIGINAL_PROJECT_ANALYSIS.md, WINDIVERT_INTEGRATION.md, WINDOWS_INTEGRATION.md.

## 1. Обзор

```
                    Пользователь
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
            GUI (egui)           CLI (clap)
              │                     │
              └──────────┬──────────┘
                         ▼
                Application Core (Core Manager)
                         │
        ┌────────┬───────┼────────┬───────────┐
        ▼        ▼       ▼        ▼           ▼
     Config  Strategy  Engine  Diagnostics  Connectivity
     Manager Manager  Manager  Manager      Checker
                         │
                         ▼
                WinDivert Adapter (safe wrapper)
                         │
                         ▼
                WinDivert FFI (unsafe, изолирован)
                         │
                         ▼
                WinDivert.dll → WinDivert64.sys
```

Windows Integration (`src/windows/`) — горизонтальный слой: права, SCM,
netsh, реестр, single-instance, IPC. Используется Core, Engine Manager
и Diagnostics, но не проникает в бизнес-логику.

## 2. Принципы

1. **Core — единственный владелец состояния.** GUI/CLI — тонкие клиенты
   публичного API Core; бизнес-логики в них нет.
2. **Состояние RUNNING — только по фактическим признакам** (открытый
   хендл WinDivert, живой рабочий цикл), не по конфигу.
3. **Изоляция unsafe**: только `windivert/ffi.rs` и точечно `windows/`.
4. **Один процесс, два интерфейса**: exe с манифестом
   `requireAdministrator` (D-008); без аргументов — GUI, с аргументами —
   CLI. Координация экземпляров — Named Pipe (D-009).
5. **Модульность по PROMPT.md, раздел 5**; модули общаются через
   типизированные контракты (MODULE_CONTRACTS.md), не через
   публичные поля.

## 3. Модули и границы ответственности

| Модуль | Ответственность | Не делает |
|---|---|---|
| `application/` | Core Manager: состояние, жизненный цикл, события, координация компонентов | WinAPI, сеть, рендеринг |
| `engine/` | Сетевой движок: рабочий цикл пакетов, применение профилей десинхронизации, статистика | Знает о GUI/CLI; хранит конфиг |
| `windivert/` | FFI + safe-адаптер WinDivert | Логика стратегий |
| `windows/` | Права, SCM, netsh, реестр, single-instance, named pipe | Решения о том, когда вызывать операции |
| `strategy/` | Профили стратегий: обнаружение, парсинг (вкл. импорт синтаксиса winws-аргументов), валидация, статусы совместимости | Применение стратегий |
| `config/` | JSON+ENV, дефолты, валидация, атомарная запись, бэкапы, версионирование схемы, миграции | Чтение чужих конфигов напрямую |
| `diagnostics/` | Проверки PASS/WARN/FAIL/BLOCKED | Исправления без подтверждения |
| `connectivity/` | DNS/TCP/TLS/HTTP-проверки, история | Гарантии доступности |
| `cli/` | Парсинг команд, вывод, коды завершения | Бизнес-логика |
| `gui/` | Отображение и ввод | Бизнес-логика |
| `logging/` | Настройка tracing, ротация | Форматирование бизнес-событий |
| `storage/` | Локальное хранение истории/состояния (JSON-файлы) | Конфигурация (это config/) |

## 4. Ключевые архитектурные решения (зафиксированы в DECISIONS.md)

- **D-007 Имя**: пакет и бинарник `mxds`; CLI `mxds <cmd>`; служба
  Windows `mxds`. Отступление от имён `zapret-rust` в PROMPT.md —
  согласовано владельцем (выбор имени проекта MXDS).
- **D-008 Модель прав**: единый процесс с манифестом
  `requireAdministrator`. Обоснование: движок требует драйвер; UX
  «запустил и забыл»; разделение UI/движок по процессам усложнило бы
  координацию без выигрыша в безопасности для локального single-user
  приложения.
- **D-009 Локальная координация**: Named Pipe `\\.\pipe\MXDS.Control`
  с DACL «текущий пользователь», JSON-lines протокол, allowlist команд
  (status/stop/run/get-logs). Без HTTP/TCP-сокетов. CLI при запущенном
  экземпляре передаёт команды через pipe; иначе работает автономно.
- **Модель потоков**: Tokio runtime для Core/Connectivity/Diagnostics;
  рабочий цикл движка — выделенный OS-поток с блокирующим
  `WinDivertRecv` (низкая латентность пакетного пути важнее async);
  мост к Tokio — каналы.
- **Event Bus**: tokio broadcast-канал с типизированными событиями
  (PROMPT.md, раздел 7); подписчики GUI/CLI/логирование; backpressure —
  вытеснение старых событий (lagged → пропуск с WARN).

## 7. Хранение

- `config/default.json` (в дистрибутиве, read-only эталон),
  `config/config.json` (пользовательский, атомарная запись + .bak).
- `profiles/*.json` — стратегии MXDS; импортированные из оригинала
  помечаются `origin: "flowseal-1.10.4"`.
- `lists/` — копии списков оригинала + `*-user.txt`.
- `assets/payloads/*.bin` — payload'ы (D-004) + `SHA256SUMS`.
- `data/` (gitignore): история connectivity, состояние, логи `logs/`.

## 8. Развёртывание и служба

- Ручной запуск: `mxds.exe` (GUI) / `mxds run` (консольный движок).
- Автозапуск: служба `mxds` (start=auto), исполняющая тот же exe с
  подкомандой `run --service`. Установка/удаление — из GUI/CLI через
  Windows Integration.
- Деинсталляция: стоп движка → удаление службы → (опционально) стоп и
  удаление служб WinDivert → файлы.
