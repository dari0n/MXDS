# Карта функциональности оригинального проекта

Дата: 2026-11-13. Источник: `divert\example` (v1.10.4).
Для каждой возможности: назначение, входы, выходы, зависимости, компоненты,
изменяемые файлы, системные требования, ограничения, переносимость на Rust,
критерии проверки. Статусы переносимости: DIRECT (прямой перенос),
REDESIGN (перенос с перепроектированием), DROP (не переносится).

## F-01. Запуск движка со стратегией (general*.bat)

- Назначение: запуск обхода DPI с выбранным набором параметров.
- Входы: bat-файл стратегии; списки lists/; payload'ы bin/*.bin; флаги
  Game Filter; права администратора.
- Выходы: работающий процесс движка; трафик обрабатывается.
- Зависимости: WinDivert (dll+sys), BFE, TCP timestamps, winws.exe.
- Компоненты: winws.exe, WinDivert.
- Изменяемые файлы: нет (кроме создания `*-user.txt` при первом запуске).
- Системные требования: Windows 10/11 x64, админ-права, свободный драйвер
  WinDivert.
- Ограничения: нет валидации параметров; нет обратной связи о реальном
  состоянии; ошибки движка видны только в консоли.
- Перенос: REDESIGN — Rust Engine + Strategy Manager (Циклы 7-8).
  Стратегии хранятся типизировано (JSON), движок — собственный.
- Критерии проверки: движок стартует, открывает WinDivert, применяет
  профили; состояние RUNNING подтверждено фактически; остановка
  освобождает драйвер.

## F-02. Установка службы автозапуска (Install Service)

- Назначение: автозапуск стратегии при загрузке Windows.
- Входы: выбранная стратегия.
- Выходы: служба `zapret` (start=auto), запись имени стратегии в реестр.
- Зависимости: sc.exe, права администратора.
- Компоненты: service.bat, SCM Windows.
- Изменяемые файлы: реестр `HKLM\...\Services\zapret`.
- Требования: админ.
- Ограничения: хрупкий парсинг bat; строка аргументов в binPath.
- Перенос: REDESIGN — Windows Integration управляет службой MXDS;
  параметры службы генерируются из типизированной стратегии, не из текста.
  Решение о модели (служба vs автозапуск с elevation) — Цикл 3.
- Критерии: служба создаётся/стартует/удаляется; после перезагрузки
  движок работает.

## F-03. Удаление служб (Remove Services)

- Назначение: полная деинсталляция обхода.
- Входы: нет. Выходы: остановлены/удалены zapret, WinDivert, WinDivert14;
  убит winws.exe.
- Перенос: DIRECT — Windows Integration (Цикл 6).
- Критерии: `sc query` не находит служб; драйвер выгружен.

## F-04. Проверка статуса (Check Status)

- Назначение: показать состояние служб zapret/WinDivert, процесса движка,
  имя активной стратегии.
- Перенос: REDESIGN — Diagnostics (Цикл 10) + Application Core state.
- Критерии: статусы соответствуют фактическому состоянию (sc query,
  дескриптор драйвера).

## F-05. Game Filter

- Назначение: расширение обхода на игровые UDP/TCP-порты (>1023).
- Входы: режим (disabled/all/tcp/udp), диапазоны портов.
- Выходы: файл `utils/game_filter.enabled`; требуется перезапуск стратегии.
- Ограничения: при disabled подставляется порт 12 (хак).
- Перенос: REDESIGN — поле конфигурации в Config Manager с валидацией
  диапазонов (перенос логики validate_game_filter_range).
- Критерии: валидация портов 1-65535, диапазоны, списки через запятую;
  применение через контролируемый перезапуск движка.

## F-06. IPSet Filter (none/any/loaded)

- Назначение: режим фильтрации по IP-списку.
- Входы: выбор режима. Выходы: перезапись/переименование ipset-all.txt.
- Ограничения: состояние кодируется содержимым файла (хрупко).
- Перенос: REDESIGN — явное поле конфигурации + данные списка хранятся
  отдельно и не разрушаются переключением.
- Критерии: переключение режима не теряет список; движок применяет режим.

## F-07. Auto-Update Check

- Назначение: фоновая проверка новой версии на GitHub.
- Входы: version.txt из репозитория. Выходы: уведомление, открытие браузера.
- Перенос: REDESIGN — опциональная проверка обновлений MXDS (конфиг,
  по умолчанию выключена; сетевые запросы только по явному согласию —
  UX-цель «запустил и забыл»).
- Критерии: таймаут 5 с, отсутствие сети не ломает запуск.

## F-08. Replace active fakes

- Назначение: замена активных payload'ов Discord/Game на другой .bin.
- Входы: тип фейка, файл. Выходы: перезапись ACTIVE_*.bin.
- Перенос: REDESIGN — выбор payload в профиле стратегии (ссылка на файл),
  без перезаписи файлов; сравнение по SHA256 сохранить для отображения.
- Критерии: движок использует выбранный payload; профиль валидирует
  наличие файла.

## F-09. Update IPSet List

- Назначение: скачивание актуального ipset-all из репозитория.
- Перенос: DIRECT (с осторожностью) — HTTPS-загрузка с таймаутом,
  атомарной записью и бэкапом предыдущего списка.
- Критерии: при ошибке сети старый список сохраняется.

## F-10. Update Hosts File

- Назначение: обновление hosts для Discord voice / веб-Telegram.
- Ограничения: оригинал лишь открывает notepad (ручное копирование).
- Перенос: REDESIGN — либо явная редактируемая операция с бэкапом hosts и
  подтверждением пользователя, либо DROP из MVP. Решение — Цикл 3.
- Критерии: hosts не повреждается; изменение обратимо.

## F-11. Диагностика (Run Diagnostics)

- Назначение: поиск типовых причин неработоспособности.
- Состав: BFE, системный прокси, TCP timestamps, Adguard, Killer, Intel
  Connectivity, Check Point, SmartByte, кириллица в пути, OneDrive,
  наличие WinDivert64.sys, VPN, Secure DNS (DoH), hosts (youtube-записи),
  зависший WinDivert, конфликтующие обходы (GoodbyeDPI и др.), очистка
  кэша Discord.
- Перенос: DIRECT+REDESIGN — Diagnostics (Цикл 10) со статусами
  PASS/WARN/FAIL/BLOCKED; авто-лечение только по подтверждению.
- Критерии: каждая проверка возвращает структурированный результат;
  ложных PASS нет.

## F-12. Тестирование стратегий (Run Tests / test zapret.ps1)

- Назначение: проверка работоспособности стратегий против целей.
- Входы: targets.txt, набор конфигов. Выходы: результаты в
  `utils/test results/`.
- Перенос: REDESIGN — Connectivity (Цикл 11) + режим прогона профилей;
  различение DNS/TCP/TLS/HTTP; история проверок.
- Критерии: отчёт по каждой цели и стратегии; отсутствие сети корректно
  отличается от FAIL стратегии.

## F-13. Проверка обновлений приложения (Check for Updates)

- См. F-07 (ручной вариант). Перенос: вместе с F-07.

## F-14. Управление пользовательскими списками (*-user.txt)

- Назначение: пользовательские домены/IP и исключения.
- Перенос: DIRECT — Strategy Manager/Config Manager читает и пишет списки;
  автосоздание при первом запуске с содержимым-плейсхолдером.
- Критерии: поддомены учитываются автоматически (семантика hostlist);
  `^host` — точное совпадение.

## F-15. Механизм десинхронизации DPI (внутри winws.exe)

- Назначение: ядро обхода — фейковые пакеты, сплиты, disorder, syndata,
  fooling ts/badseq, cutoff, repeats, L7-фильтры (discord/stun),
  hostlist/ipset-фильтрация.
- Входы: параметры стратегии, трафик из WinDivert.
- Перенос: REDESIGN — собственный Rust Engine (Цикл 7). Это основной
  объём работы. Требует реализации: парсера пакетов (Ethernet/IP/TCP/UDP),
  вычисления checksum, генерации фейков, фрагментации TLS ClientHello,
  QUIC Initial fake, обработки по профилям.
- Критерии: поведенческая эквивалентность оригиналу на контрольных
  стратегиях (сравнение доступности целей до/после).

## F-16. Защита от конфликтов (единственный экземпляр)

- Оригинал: предупреждение при запущенной службе; tasklist winws.exe.
- Перенос: REDESIGN — single-instance + локальная координация CLI/GUI
  (PROMPT.md, раздел 9).
- Критерии: второй экземпляр не перехватывает драйвер; команды CLI
  доходят до работающего приложения.
