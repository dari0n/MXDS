# Руководство по профилям MXDS

Профиль — это набор правил обхода DPI (какие пакеты перехватывать и какие
техники применять). Профили хранятся в `profiles/<id>.json` в типизированном
формате MXDS (импортированном из winws-стратегий оригинала). Активный профиль
выбирается в GUI или `mxds run --profile <id>`.

## 1. Создание профиля

### Через GUI

Экран **Профили** → раскрыть «Создать профиль»:
- **id** — slug `[a-z0-9-]`, станет именем файла `profiles/<id>.json`;
- **На основе** — существующий профиль-шаблон (рекомендуется) или пустой
  шаблон;
- Название и описание — произвольный текст.

Кнопка «Создать» пишет файл атомарно и обновляет список.

### Через CLI

```powershell
# Копия существующего профиля (рекомендуется — правила уже рабочие)
mxds profiles create my-test --from general-alt6 --name "Мой тест" --description "эксперимент"

# Пустой шаблон (одно правило TCP/443 по list-general.txt, без desync)
mxds profiles create my-empty
```

Ошибки: дубликат id, плохой slug, несуществующий `--from`, невалидная
структура — команда завершается кодом 1 с сообщением.

### Вручную

Скопируйте любой `profiles/general-altN.json` под новым именем и
отредактируйте. Структура:

```jsonc
{
  "id": "my-profile",            // должен совпадать с именем файла
  "meta": { "name": "...", "description": "...", "version": "1.0", "origin": "custom" },
  "wf_tcp": "80,443",            // глобальный фильтр захвата TCP (порты)
  "wf_udp": "443",               // то же для UDP
  "rules": [                     // правила применяются по порядку
    {
      "protocol": "Tcp",         // или "Udp"
      "ports": "443",            // порты/диапазоны: "80,443", "19294-19344"
      "hostlists": ["lists/list-general.txt"],   // списки доменов
      "ipsets": [],              // списки IP-подсетей
      "desync": {
        "techniques": ["Fake"],  // Fake, Multisplit, Multidisorder,
                                 // Syndata, HostFakeSplit, FakeSplit
        "repeats": 2,            // повторы фейкового пакета
        "split_pos": [{ "Absolute": 1 }],   // позиции сплита
        "fooling": ["BadSeq"],   // Ts, BadSeq, Md5Sig
        "cutoff": 3,             // прекратить desync после N пакетов
        "fakes": { "tls": "bin/tls_clienthello_www_google_com.bin" }
      }
    }
  ]
}
```

Правила применяются к первому подходящему пакету соединения (cutoff
ограничивает число обрабатываемых пакетов). Полный справочник полей —
`src/strategy/profile.rs`; матрица оригинальных стратегий —
`docs/STRATEGY_COMPATIBILITY.md`.

## 2. Проверка профиля на своей сети

Единственный надёжный способ — живой прогон (ТСПУ провайдеров различаются):

```powershell
# Перебор ВСЕХ профилей (один UAC-запрос, ~5–8 минут):
powershell -File scripts\profile-sweep.ps1 -DistDir <каталог MXDS>

# Точечно выбранные профили и цели:
powershell -File scripts\verify-profiles.ps1 -DistDir <каталог MXDS> `
    -Profiles my-test,general-alt6 -Targets "https://discord.com/"
```

Скрипт пишет `profile_sweep.log` / `verify_profiles.log`: для каждого
профиля HTTP-код и время ответа целей.

Читаемость результатов: `200/301/403` — цель отвечает (403 от CDN — это
нормально, значит TLS прошёл); `000` за ~0.1 с — провайдер шлёт RST;
`000` за 12+ с — таймаут (молчаливая блокировка).

## 3. Отметка результата (совместимость)

Статусы хранятся в `data/profile-compat.json` и показываются бейджами
в GUI и CLI (`?` не тестирован, `✓` работает, `~` частично, `✗` не работает).

```powershell
mxds profiles mark general ok --note "youtube 200 за 0.7с, discord RST"
mxds profiles mark general-alt6 partial --note "discord.com открывается, gateway RST"
mxds profiles mark my-test reset        # сбросить статус
```

В GUI: клик по бейджу совместимости в строке профиля переключает статус
по циклу `? → ✓ → ~ → ✗`; заметка показывается в подсказке бейджа.

Статус не влияет на работу движка — это памятка, какой профиль подходит
вашей сети.

## 4. Рекомендации

- Начинайте с копии ближайшего рабочего профиля (`--from`), а не с пустого
  шаблона.
- Меняйте одну технику за раз: repeats → split_pos → fooling → cutoff.
- Для Discord голоса важны UDP-правила (443/50000-65535); для сайтов — TCP/443.
- Не экспериментируйте с чужими сетями и сторонними системами.
