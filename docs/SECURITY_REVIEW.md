## 2. Целостность поставляемых бинарников

Факты (проверено 2026-11-13 на копии из divert\example):
- `WinDivert64.sys` v2.2 — подпись Authenticode валидна.
- `WinDivert.dll` — не подписана (типично для WinDivert).
- `winws.exe` — не используется в MXDS вообще.

Меры MXDS:
1. При старте движок проверяет SHA256 `WinDivert.dll`/`WinDivert64.sys`
   против зафиксированных в дистрибутиве хэшей; расхождение → FAIL
   диагностики, движок не стартует.
2. Хэши фиксируются при сборке релиза (Цикл 16) и публикуются в
   ACCEPTANCE_REPORT.md.
3. Проверка Authenticode-подписи .sys через WinVerifyTrust — в
   диагностике (WARN при невалидной, FAIL при отсутствии подписи драйвера).

## 3. Антивирусы

WinDivert классифицируется частью антивирусов как RiskTool/PUA
(задокументировано оригиналом). MXDS:
- НЕ обходит и НЕ отключает антивирусы.
- Диагностирует ERROR_DRIVER_BLOCKED (1275) и выдаёт пользователю
  рекомендацию: добавить папку MXDS в исключения или отключить детект PUA
  (со ссылкой на объяснение).
- Документирует это в README.

## 4. Привилегии

- Админ-права нужны только для операций с драйвером/службами/netsh
  (см. WINDOWS_INTEGRATION.md, раздел 2). Приложение не повышает права
  скрытно; каждый запрос elevation виден пользователю (UAC).
- Локальная координация (CLI↔GUI): Named Pipe с DACL «только текущий
  пользователь»; команды валидируются по allowlist; произвольное
  выполнение команд ОС отсутствует (PROMPT.md, Цикл 12).

## 5. Данные и секреты

- Секретов в приложении нет (ни токенов, ни ключей); ENV и JSON не
  должны содержать секретов — валидация предупреждает о ключах вида
  `*KEY*/*SECRET*/*TOKEN*` в конфиге.
- Логи: tracing с фильтрацией; пути и конфиги логируются, содержимое
  пакетов — никогда (только метаданные: 5-tuple, размер).
- История проверок доступности хранится локально, без отправки.

## 6. Сетевое поведение

- Исходящие соединения MXDS: только (а) проверки доступности целей
  (Цикл 11), (б) опциональные обновления списков/версии — по явной
  настройке, с таймаутами. Скрытых сетевых серверов нет; приложение не
  слушает сокеты (кроме Named Pipe локальной координации).
- Движок модифицирует трафик согласно выбранной стратегии (D-001);
  обработка ограничена фильтрами стратегии; штатная сеть не затрагивается
  при остановленном движке.

## 7. unsafe-политика

- unsafe только в `src/windivert/ffi.rs` и точечно в `src/windows/`
  (WinAPI-обёртки), каждый блок — с обоснованием (SAFETY-комментарий)
  и проверками инвариантов.
- `#![forbid(unsafe_code)]` в модулях GUI/CLI/config/strategy/application.

## 8. Отказоустойчивость и «не оставить систему хуже»

- При остановке/крахе: дескрипторы WinDivert закрываются (Drop),
  фильтры снимаются драйвером автоматически при закрытии хендла.
- Любые системные изменения (TCP timestamps, службы) документируются,
  обратимы и выполняются с подтверждения.
- Повреждённая конфигурация → восстановление из бэкапа, приложение не
  запускает движок на невалидной конфигурации.

## 9. Известные риски (на Цикл 2)

| Риск | Уровень | Митигация |
|---|---|---|
| Антивирус блокирует драйвер | Средний | Диагностика + инструкция по исключениям |
| Конфликт с другими обходами (GoodbyeDPI и др.) | Средний | Детекция по SCM, статус BLOCKED |
| Зависший драйвер WinDivert после краха | Низкий | Детекция «осиротевшей» службы при старте |
| Неподписанная DLL подменена | Средний | Проверка SHA256 при старте |
| Кириллица/OneDrive в пути | Низкий | Диагностика при установке/запуске |
